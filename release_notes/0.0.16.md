## Dashboard: no more copying files

The dashboard page now ships **inside** the integration and Home Assistant serves it for you. There is nothing to copy into `<config>/www` any more.

Point your iframe card at the new URL:

```yaml
type: iframe
url: /cellartracker/cellar.html
aspect_ratio: 100%
title: My Wine Collection
```

Previously the README told HACS users to copy `custom_components/www/cellar.html` into `<config>/www`. That source path never existed on their system — HACS installs `custom_components/cellar_tracker` and nothing else — so anyone following the instructions hit a missing file and could not use the bottle table at all.

**Upgrading?** If you already copied the page, `/local/cellar.html` keeps working — Home Assistant's `www` mount is untouched. It is a stale copy that will not pick up fixes, so repoint your card at `/cellartracker/cellar.html` and delete `<config>/www/cellar.html` when convenient.

## ⚠️ Requires Home Assistant 2024.7 or newer

That is the release that added the static-path API used to serve the page.

## Fixes

* The HTTP views are registered once for the component instead of once per config entry, so reloading no longer risks registering the same route twice.
* Unloading a config entry that failed partway through setup no longer raises `KeyError`.
* The bottle-count and cellar-value sensors return their defaults instead of raising when the coordinator has not completed its first refresh.
* `iot_class` corrected to `cloud_polling`, manifest keys sorted, and `hacs.json` trimmed to the keys HACS accepts — hassfest and HACS validation now pass.
* The repository is now MIT licensed.
