## Nothing to do

This release changes nothing you can see. No new entities, no renamed ones, no
attributes added or removed, no settings to revisit, and the same minimum of
**Home Assistant 2024.11**. Every sensor keeps its entity ID, its state and its
history. If you update and notice a difference, that is a bug — please report it.

It is worth cutting anyway, because of what it changes about the *next* release.

## The integration is now checked against Home Assistant itself

Home Assistant offers integrations a lot of typed machinery — what a data
coordinator holds, what a config entry carries, what a sensor may return. Until
now none of that was verified here. The code said what it meant, and nobody
checked whether Home Assistant agreed.

It does now, on every push: the integration is type-checked against a real
Home Assistant install, and four places where this code had been calling the
framework incorrectly are fixed. None of them was reachable while the
integration was running, which is exactly why they had survived — they were the
kind of mistake that sits quietly until a Home Assistant release changes
something underneath it, and then breaks a cellar on a Tuesday morning.

The internal shape of a poll's results is also named and checked now, so a
misspelled key inside the integration fails the build rather than turning a
sensor into `unknown` for whoever updates first.

## About the check that was checking nothing

The first attempt at this shipped a type checker that could not see Home
Assistant, which quietly reduced every framework type to "anything goes". It
reported success over code it had never looked at — worse than having no check,
because the result gets believed.

That is fixed, and the fix is tested the only way this sort of thing can be:
the build now fails deliberately if the checker ever loses sight of Home
Assistant again.

Credit to the review bot on
[#19](https://github.com/GuvHas/cellartracker/pull/19) for catching it before
it reached anyone.
